# AI Repository Summary

> This document provides a comprehensive overview of the repository for AI agents and developers.

## Repository Overview

**Name:** workflow-orchestration-queue (OS-APOW)  
**Description:** Headless agentic orchestration platform that transforms GitHub Issues into automated execution orders for AI-driven development.  
**Primary Language:** Python 3.12+  
**Package Manager:** uv

## Project Purpose

This system replaces the traditional "interactive AI coding" paradigm with a persistent, event-driven infrastructure. Instead of requiring human-in-the-loop guidance, it autonomously:

1. Ingests GitHub webhooks (issues, comments, PRs)
2. Queues tasks via GitHub labels
3. Dispatches specialized AI agents to implement features
4. Creates Pull Requests for human review

## Architecture

### The Four Pillars

| Pillar | Component | Technology | Purpose |
|--------|-----------|------------|---------|
| The Ear | Notifier Service | FastAPI, Pydantic | Webhook ingestion and HMAC verification |
| The State | GitHub Issues | Labels, Assignees | Distributed state management |
| The Brain | Sentinel | Python async | Polling, claiming, dispatching |
| The Hands | Worker | opencode CLI, Docker | Code execution in isolated containers |

### Key Files

```
src/
├── notifier_service.py      # FastAPI webhook receiver (port 8000)
├── orchestrator_sentinel.py # Background polling service
├── models/
│   ├── work_item.py         # Unified task representation + scrub_secrets()
│   └── github_events.py     # GitHub webhook payload schemas
└── queue/
    └── github_queue.py      # ITaskQueue interface + GitHub implementation
```

### State Machine

| Label | Meaning |
|-------|---------|
| `agent:queued` | Task validated, awaiting Sentinel |
| `agent:in-progress` | Sentinel claimed the issue |
| `agent:success` | Workflow completed successfully |
| `agent:error` | Technical failure occurred |
| `agent:infra-failure` | Infrastructure failure (timeout, OOM) |

## Development Setup

### Prerequisites

- Python 3.12+
- uv package manager
- Docker (for worker containers)
- GitHub CLI (gh)

### Quick Start

```bash
# Install dependencies
uv pip install -e ".[dev]"

# Run notifier service
uvicorn src.notifier_service:app --reload

# Run sentinel (separate terminal)
python -m src.orchestrator_sentinel
```

### Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `GITHUB_TOKEN` | Yes | GitHub App Installation Token |
| `GITHUB_REPO` | Yes | Target repository (owner/repo) |
| `SENTINEL_BOT_LOGIN` | Yes | Bot account login for task locking |
| `WEBHOOK_SECRET` | No | HMAC secret for webhook verification |
| `SENTINEL_POLL_INTERVAL` | No | Polling interval in seconds (default: 60) |

## Key Patterns

### Assign-Then-Verify (Distributed Locking)

1. Assign sentinel to issue
2. Re-fetch the issue
3. Verify assignment before proceeding

### Shell-Bridge Execution

All worker interactions go through `scripts/devcontainer-opencode.sh`:
- `up` - Provision network and volumes
- `start` - Launch opencode server
- `prompt "{workflow}"` - Dispatch work
- `stop` - Clean up

### Secret Scrubbing

The `scrub_secrets()` function removes:
- GitHub PATs (`ghp_*`, `ghs_*`, `gho_*`, `github_pat_*`)
- Bearer tokens
- OpenAI keys (`sk-*`)
- ZhipuAI keys
